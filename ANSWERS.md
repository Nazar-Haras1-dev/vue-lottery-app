# Лаба 4: відповіді на контрольні запитання

1. **Computed** це обчислювана властивість: значення, що виводиться з інших реактивних даних (`computed(() => a.value + b.value)`). Від методу відрізняється **кешуванням**: метод виконується при кожному виклику/перемальовуванні, computed перераховується лише коли змінилась залежність.
2. Результат **кешується** і перераховується тільки тоді, коли змінилась хоча б одна реактивна залежність, яку він прочитав. Якщо залежності не змінились, повертається збережене значення.
3. За замовчуванням computed **лише для читання**. Writable computed задають з `get` і `set`: `computed({ get: () => x.value, set: (v) => { x.value = v } })`. У проєкті так зроблено `isEditOpen`.
4. Обробники: **inline** (вираз прямо в шаблоні: `@click="count++"`) та **метод** (`@click="save"`). Inline підходить для коротких дій, метод для складної логіки (його можна перевикористовувати, тестувати та отримувати `event`).
5. `.prevent` = `event.preventDefault()` (`@submit.prevent`), `.stop` зупиняє спливання, `.once` спрацьовує один раз (`@click.once`). Ключові: `.enter`, `.esc` реагують на клавішу: `@keydown.enter="submit"`, `@keydown.esc="close"` (так у формі й модалці).
6. `v-model` це двостороннє зв'язування. Для текстового поля еквівалент: `<input :value="text" @input="text = $event.target.value">`.
7. `checkbox` → boolean (або масив для групи), `radio` → значення вибраної кнопки, `select` → значення вибраного `option`, `textarea` → текст (так само, як input; без `{{ }}` усередині).
8. `.lazy` оновлює модель після `change`, а не `input`; `.number` перетворює значення на число; `.trim` прибирає пробіли по краях.
9. Валідація: функція повертає об'єкт помилок (обов'язкові поля, `EMAIL_REGEX`, `PHONE_REGEX = /^\+380\d{9}$/`, порівняння дати з сьогоднішньою). Помилки виводяться в шаблоні під полем (`v-if="error"`) з Bootstrap-класом `invalid-feedback`, а не через `alert`.
10. Після збереження скинути значення полів і прапорці `touched` та `submitted`. Оскільки помилки показуються лише при цих прапорцях, порожня форма виглядає «чистою».
11. **Props** це дані, які **батько передає дитині** (однонаправлений потік: батько → дитина).
12. Props керує батько; прямі зміни дають попередження та ламають потік даних. Правильно: або емітувати подію, щоб батько змінив значення, або зробити локальну копію (`ref(props.x)`), або використати `v-model`/`defineModel`.
13. `defineProps<{ name: string; age?: number }>()`: `?` робить проп необов'язковим. Значення за замовчуванням: `withDefaults(defineProps<...>(), { age: 18 })`. Обов'язковість визначається відсутністю `?`.
14. Дитина викликає **`emit`**. Оголошення з типами: `const emit = defineEmits<{ edit: [p: Participant]; remove: [] }>()`, виклик: `emit('edit', participant)`. Батько слухає `@edit="..."`.
15. Через `defineModel`: `const model = defineModel<string>()`. Тоді батько пише `<BaseInput v-model="name" />`. (Альтернатива: проп `modelValue` + подія `update:modelValue`.)
16. **Слоти** дозволяють батьку вставляти розмітку всередину дочірнього компонента. Слот за замовчуванням один (`<slot />`), **іменовані** (`<slot name="footer" />`, у батька `<template #footer>`) дають кілька місць для вставки. У `BaseModal`: тіло та футер з кнопками «Так / Ні».
17. **Watcher** виконує побічний ефект при зміні даних (запис у localStorage, запит, подія з debounce). **Computed** повертає нове значення й не має побічних ефектів. Якщо треба «порахувати значення», використовуй computed; якщо «зробити дію», використовуй watch.
18. `deep: true` стежить за вкладеними змінами об'єкта/масиву; `immediate: true` виконує callback одразу при створенні. **`watchEffect`** автоматично відстежує все, що прочитав усередині, і запускається одразу; `watch` явно вказує джерело й дає старе та нове значення.
19. `watch(participants, v => localStorage.setItem(KEY, JSON.stringify(v)), { deep: true })` для збереження; при старті `ref(JSON.parse(localStorage.getItem(KEY) ?? '[]'))` для відновлення (з `try/catch`).
20. Принципи: одна відповідальність, малі компоненти, дані вниз (props) / події вгору (emit), стан у одному місці. **Reusable-компонент** не знає про конкретний контекст і налаштовується через props/slots (`BaseButton`, `BaseInput`, `BaseModal`).
21. Усе в одному `computed`: `props.participants.filter(...)` за пошуком, потім `.sort(...)` за вибраним ключем і напрямком. Вихідний список не змінюється.
22. **Options API** групує код за опціями (`data`, `methods`, `computed`), простіший для початківців. **Composition API** групує код за логікою, дає кращу типізацію з TypeScript, повторне використання через composables і менше «магії з `this`». Для великих застосунків краще підходить Composition API.
